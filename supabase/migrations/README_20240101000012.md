# Migration 20240101000012: Workspace Task Management Enhancements

## Overview

This migration adds comprehensive task management enhancements to support:
- Team Lead (TL) task management with the same workflow as team members
- Peer review system for task submissions
- Task submission modification capabilities
- Task assignment revocation
- Enhanced visibility of task submissions across the workspace

## Changes Made

### 1. New Columns Added to `tasks` Table

| Column Name | Type | Description |
|------------|------|-------------|
| `started_at` | TIMESTAMP WITH TIME ZONE | Tracks when a task was started by the assignee |
| `submission_file_size` | INTEGER | Stores the size of the submitted file in bytes |

### 2. New Table: `task_reviews`

A new table to store peer reviews for task submissions.

**Schema:**
```sql
CREATE TABLE task_reviews (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  task_id UUID NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  reviewer_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  action VARCHAR(20) NOT NULL CHECK (action IN ('approve', 'request_redo')),
  comments TEXT,
  reviewed_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

**Features:**
- Tracks who reviewed each task
- Records the review action (approve or request redo)
- Stores optional feedback comments
- Maintains audit trail with timestamps
- Cascading deletes when tasks or users are removed

### 3. Performance Indexes

Six new indexes were added to optimize query performance:

| Index Name | Table | Columns | Purpose |
|-----------|-------|---------|---------|
| `idx_tasks_workspace_assigned` | tasks | workspace_id, assigned_to | Fast lookup of tasks by workspace and assignee |
| `idx_tasks_status` | tasks | status | Quick filtering by task status |
| `idx_tasks_workspace_submissions` | tasks | workspace_id, submitted_at | Efficient retrieval of submissions (partial index) |
| `idx_task_reviews_task` | task_reviews | task_id | Fast lookup of reviews by task |
| `idx_task_reviews_reviewer` | task_reviews | reviewer_id | Quick access to reviews by reviewer |
| `idx_task_reviews_task_reviewer` | task_reviews | task_id, reviewer_id | Composite index for combined queries |

### 4. Row Level Security (RLS) Policies

#### task_reviews Table Policies

1. **"Workspace members can review tasks"** (INSERT)
   - Allows workspace members to create reviews for tasks in their workspace
   - Applies to both regular members and workspace owners

2. **"Users can view task reviews in their workspaces"** (SELECT)
   - Allows workspace members to view all reviews in their workspace
   - Workspace owners can view all reviews in their workspaces

3. **"Users can view reviews for their assigned tasks"** (SELECT)
   - Allows users to view reviews for tasks assigned to them
   - Ensures task assignees can see feedback on their work

#### Storage Policies

1. **"Workspace members can view task submissions"** (SELECT)
   - Enhanced policy allowing all workspace members to view submissions
   - Replaces previous policy with better access control
   - Supports:
     - Users viewing their own submissions
     - Workspace owners viewing all submissions
     - Workspace members viewing all submissions in their workspace

## Requirements Addressed

This migration addresses the following requirements from the spec:

- **1.1**: TL can view their own assigned tasks
- **1.6**: TL's tasks can be reviewed by workspace members
- **2.1**: TL can see all workspace members and their tasks
- **3.1**: Workspace members can view all uploaded documents
- **4.1**: Members can modify submissions (delete/re-upload)
- **5.1**: TL can revoke task assignments
- **6.1**: Workspace members can review TL submissions

## Rollback Plan

If you need to rollback this migration:

```sql
-- Drop task_reviews table (cascades to policies and indexes)
DROP TABLE IF EXISTS task_reviews CASCADE;

-- Remove new columns from tasks table
ALTER TABLE tasks DROP COLUMN IF EXISTS started_at;
ALTER TABLE tasks DROP COLUMN IF EXISTS submission_file_size;

-- Drop indexes on tasks table
DROP INDEX IF EXISTS idx_tasks_workspace_assigned;
DROP INDEX IF EXISTS idx_tasks_workspace_submissions;

-- Restore original storage policy
DROP POLICY IF EXISTS "Workspace members can view task submissions" ON storage.objects;

-- Recreate original policy (if needed)
CREATE POLICY "Users can view task submissions in their workspaces" ON storage.objects
  FOR SELECT USING (
    bucket_id = 'task-submissions' AND (
      auth.uid()::text = (storage.foldername(name))[1] OR
      auth.uid() IN (
        SELECT w.created_by 
        FROM workspaces w
        JOIN tasks t ON t.workspace_id = w.id
        WHERE t.id::text = (storage.foldername(name))[2]
      )
    )
  );
```

## Performance Considerations

- **Indexes**: The new indexes will improve query performance but may slightly slow down INSERT/UPDATE operations on the `tasks` and `task_reviews` tables
- **Storage Impact**: Minimal - two new columns on existing table, one new table for reviews
- **Query Optimization**: The composite indexes are designed to support the most common query patterns in the application

## Security Considerations

- **RLS Policies**: All policies follow the principle of least privilege
- **Cascading Deletes**: Reviews are automatically deleted when tasks or users are removed
- **Storage Access**: Enhanced to allow workspace collaboration while maintaining security
- **Audit Trail**: The `task_reviews` table maintains a complete audit trail of all review actions
